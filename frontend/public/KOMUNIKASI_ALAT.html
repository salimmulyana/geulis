BAGIAN A — PENGGUNAAN APLIKASI

A1. Masuk (Login) & Peran Pengguna

Buka http://[IP_SERVER]:5173 di browser, masukkan username dan password. Setelah berhasil, menu yang tampil di sidebar menyesuaikan hak akses peran Anda.

Ada dua peran bawaan:

PeranAkses
Administrator (admin)Semua menu, termasuk User & Hak Akses dan Pengaturan Sistem. Bisa menghapus data.
Petugas Lab (lab)Dashboard, Data Pasien, Permintaan Lab, dan Hasil Lab. Tidak bisa mengelola user/pengaturan.
Menu & tombol muncul/hilang otomatis sesuai hak akses. Contoh: tombol Hapus pasien hanya terlihat oleh Administrator. Untuk keluar, klik 🚪 Keluar di bawah sidebar.

A2. Dashboard Pemantauan

Halaman pertama setelah login. Menampilkan ringkasan operasional harian:

  • Kartu statistik: Permintaan Pending, Permintaan Hari Ini, Hasil Hari Ini, Total Pasien.
  • Status Alat Lab: daftar alat, port, dan waktu terakhir terhubung — untuk memastikan alat aktif.
  • Hasil Kritis / Abnormal: hasil terbaru yang di luar nilai rujukan (perlu perhatian segera).
  • Permintaan Terbaru: order lab terakhir beserta status & prioritasnya.

A3. Data Pasien

Menu 👤 Data Pasien untuk mengelola identitas pasien.

  • Cari: ketik nama atau No. RM di kotak pencarian (otomatis menyaring).
  • Tambah (tombol + Pasien Baru): isi No. Rekam Medis & Nama (wajib), lalu Tgl Lahir, Jenis Kelamin, Telepon, Alamat (opsional). Klik Simpan.
  • Edit: ubah data pasien yang sudah ada.
  • Hapus: hanya Administrator.
No. Rekam Medis harus unik. Pasien juga bisa terbentuk otomatis dari order SIMRS (bridging) atau dari hasil alat yang barcode-nya belum dikenal — lihat Bagian B-5.

A4. Permintaan Lab & Alur Status

Menu 🧪 Permintaan Lab adalah pusat order pemeriksaan. Data auto-refresh tiap 15 detik.

Membuat permintaan baru

  1. Klik + Permintaan Baru.
  2. Pilih Pasien dan Prioritas (Normal / Cito / STAT).
  3. Centang Pemeriksaan yang diminta (bisa dicari; klik baris untuk memilih).
  4. Isi Catatan bila perlu, lalu Simpan.

Alur status (tombol aksi berubah sesuai status)

pending  ──[Ambil Sampel]──▶  collected  ──[Proses Sampel]──▶  processing  ──[Selesai]──▶  completed
StatusArti & aksi tersedia
pendingBaru diorder. Bisa Edit atau Ambil Sampel.
collectedSampel diambil. Aksi: Proses Sampel.
processingSedang dikerjakan. Bisa Isi/Edit Hasil, Lihat Hasil, atau Selesai.
completedSelesai. Masih bisa Isi/Edit Hasil & Lihat Hasil.
Filter berdasarkan status dan rentang tanggal (maks. 31 hari). Menghapus permintaan juga menghapus semua hasil yang terhubung.

A5. Mengisi Hasil Pemeriksaan

Ada tiga cara hasil masuk ke sistem:

  1. Otomatis dari alat — hasil langsung tersimpan saat alat mengirim data (lihat Bagian B).
  2. Isi per permintaan — di menu Permintaan Lab, tombol 📝 Isi / Edit Hasil pada order berstatus processing/completed. Muncul daftar parameter order tersebut; ketik nilainya. Kolom Tampil Cetakan menentukan apakah parameter itu ikut dicetak di laporan. Klik Simpan Hasil.
  3. Input manual bebas — di menu Hasil Lab, tombol + Input Manual: pilih pasien (dari order aktif), pemeriksaan, nilai, dan satuan.
Flag otomatis: setiap nilai dibandingkan dengan nilai rujukan pemeriksaan → diberi tanda normal / low / high / critical / abnormal. Nilai jauh di luar rentang (<70% atau >130%) ditandai critical.

A6. Melihat & Mencetak Hasil

Menu 📋 Hasil Lab menampilkan hasil dikelompokkan per pasien per tanggal. Cari berdasarkan nama/No. RM dan saring rentang tanggal (maks. 31 hari).

  • 📄 Lihat Hasil — membuka Lembar Hasil Laboratorium: kop instansi (dari Pengaturan), identitas pasien, tabel hasil (Pemeriksaan, Hasil, Satuan, Nilai Rujukan, Keterangan), dan kolom tanda tangan pemeriksa.
  • 🖨️ Cetak — mencetak lembar hasil (format A4 portrait). Nilai abnormal ditandai tebal + tanda *.
  • Hapus — menghapus seluruh hasil pasien pada tanggal tersebut.
Hanya parameter dengan Tampil Cetakan aktif dan tes yang ditampilkan di laporan yang muncul di cetakan. Urutan pemeriksaan mengikuti sort_order katalog tes.

A7. Alat Laboratorium

Menu ⚙️ Alat Laboratorium untuk mendaftarkan analyzer, mengelola pemetaan kode pemeriksaan, dan memantau log komunikasi.

  • Tambah/Edit alat: kode, nama, protokol (ASTM/HL7/JSON/XML), dan Port TCP.
  • Auto-mapping: kode tes dari alat otomatis terdaftar saat sampel pertama masuk — Anda tinggal merapikan nama, satuan, dan nilai rujukan.
  • Log komunikasi: memantau data masuk/keluar (<ENQ>, <ACK>, record hasil) untuk troubleshooting.
Detail teknis lengkap (cara alat terhubung, protokol, port, host query dua arah) ada di Bagian B. Penting: setelah menambah alat / mengubah port, backend harus di-restart agar port listener terbuka — lihat Bagian B-2.

A8. User & Hak Akses

Menu 🔐 User & Hak Akses (khusus yang berhak). Dua tab:

  • Daftar User: tambah user (username, password, nama, email, role), ubah Password, dan hapus user. Kolom menampilkan status aktif & login terakhir.
  • Hak Akses Role: pilih role, lalu centang izin per-menu (lihat/kelola Dashboard, Permintaan, Pasien, Hasil, User, Mapping, Alat). Klik Simpan Hak Akses. Perubahan langsung berlaku bagi semua user pada role tersebut.

A9. Pengaturan Sistem (Profil Klinik & API)

Menu ⚙️ Pengaturan Aplikasi (khusus Administrator). Dua tab:

  • Profil Klinik: nama klinik/RS, alamat, telepon, email, dan logo (maks. 2MB). Data ini menjadi kop pada cetakan hasil lab.
  • Integrasi API: buat & kelola API Key untuk SIMRS/aplikasi eksternal. API Key hanya ditampilkan sekali saat dibuat — simpan baik-baik. Tersedia tombol Lihat Dokumentasi API (bridging order & tarik hasil).
API Key memberi akses baca/tulis data medis. Jaga kerahasiaannya; cabut (hapus) bila tidak dipakai.

A11. Bridging dengan SIMRS (REST API)

GeuLIS menyediakan REST API agar SIMRS (atau aplikasi lain) dapat mengirim permintaan lab dan menarik hasil secara otomatis, tanpa input ulang. Dua endpoint utama:

FungsiEndpointMethod
SIMRS mengirim order/bridging/orderPOST
SIMRS menarik hasil/bridging/result/{simrs_order_id}GET

Langkah 1 — Buat API Key

Login sebagai Administrator → menu Pengaturan Aplikasi → tab Integrasi API → + Generate Key Baru. Salin key (format khanza_...) — hanya ditampilkan sekali. Setiap request wajib menyertakan header:

HeaderNilai
x-api-keyAPI Key dari LIS (mis. khanza_CONTOH123)
Content-Typeapplication/json

Langkah 2 — SIMRS Mengirim Order

POST http://[IP_SERVER]:3001/bridging/order

FieldWajibKeterangan
simrs_order_idYaNomor order dari SIMRS. Harus unik.
medical_record_noYaNo. Rekam Medis pasien.
patient_nameYaNama pasien.
testsYaArray kode pemeriksaan. Bisa kode LIS (mis. HGB) atau kode SIMRS (mis. 3962) — LIS menerjemahkan otomatis via mapping.
genderTidakL / P. Default L.
birth_dateTidakFormat YYYY-MM-DD.
priorityTidaknormal / cito / stat.
notesTidakCatatan klinis.

Contoh request:

curl -X POST http://[IP_SERVER]:3001/bridging/order \
  -H "x-api-key: khanza_xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "simrs_order_id": "ORD-20260724-001",
    "medical_record_no": "RM-000123",
    "patient_name": "Budi Santoso",
    "gender": "L",
    "birth_date": "1990-05-15",
    "tests": ["HGB", "WBC"]
  }'

Respons sukses (LIS otomatis membuat pasien bila belum ada):

{
  "message": "Order berhasil diterima",
  "data": {
    "request_no": "REQ20260724999107",
    "simrs_order_id": "ORD-20260724-001",
    "patient_id": 28,
    "request_id": 27
  }
}
Jika simrs_order_id sudah pernah dikirim → HTTP 409. Jika kode tes tidak dikenal → HTTP 400. Tanpa API key valid → HTTP 401.

Langkah 3 — SIMRS Menarik Hasil

GET http://[IP_SERVER]:3001/bridging/result/{simrs_order_id}

curl http://[IP_SERVER]:3001/bridging/result/ORD-20260724-001 \
  -H "x-api-key: khanza_xxxxxxxx"

Respons — setiap item hasil punya status pending (belum keluar) atau completed (sudah ada nilai):

{
  "simrs_order_id": "ORD-20260724-001",
  "request_no": "REQ20260724999107",
  "status": "completed",
  "patient": { "medical_record_no": "RM-000123", "name": "Budi Santoso", ... },
  "results": [
    {
      "test_code": "HGB",
      "code_simrs": "3962",
      "test_name": "Hemoglobin",
      "result_value": "14.2",
      "unit": "g/dL",
      "reference": "12 - 17.5",
      "flag": "normal",
      "result_time": "2026-07-24 08:15:00",
      "status": "completed"
    }
  ]
}
Pola pemakaian SIMRS: kirim order sekali saat dokter meminta lab, lalu polling endpoint hasil secara berkala (mis. tiap beberapa menit) hingga semua item ber-status completed.
Dokumentasi API teknis lengkap tersedia di tombol Lihat Dokumentasi API (menu Pengaturan → Integrasi API), atau buka /API_BRIDGING.html.

A12. Fitur Lanjutan

A12.1. Verifikasi Hasil 2 Tahap

Hasil yang masuk otomatis dari alat berstatus preliminary (belum divalidasi) dan belum bisa ditarik SIMRS sebagai "completed". Analis memeriksa lalu memverifikasi sehingga status menjadi final.

  • Di menu Hasil Lab, kolom Status menampilkan ⏳ n belum verifikasi atau ✓ Terverifikasi.
  • Klik tombol ✓ Verifikasi pada baris pasien untuk memvalidasi semua hasil tanggal itu sekaligus.
  • Setelah diverifikasi, hasil menjadi final dan (bila SIMRS aktif) otomatis di-push ke SIMRS.
Hasil yang diketik manual oleh petugas langsung dianggap final (sudah divalidasi manusia). Yang perlu verifikasi hanya hasil otomatis dari alat.

A12.2. Notifikasi Hasil Kritis

Hasil dengan flag critical (jauh di luar nilai rujukan) muncul sebagai banner merah di Dashboard. Petugas menekan ✓ Tindak lanjut untuk menandai bahwa hasil sudah dihubungi/ditindaklanjuti (acknowledge). Banner berkurang setiap ada yang ditindaklanjuti dan menyegar otomatis tiap 20 detik.

A12.3. Log Audit

Menu 📜 Log Audit (Administrator) mencatat setiap perubahan data: siapa (user), kapan, aksi (CREATE/UPDATE/DELETE/VERIFY/ACK/PUSH/LOGIN), entitas, dan detail. Bisa disaring per entitas atau dicari. Berguna untuk penelusuran & kepatuhan data medis.

A12.4. Grafik Tren Hasil

Di menu Hasil Lab, tombol 📈 Tren menampilkan grafik perkembangan nilai satu pemeriksaan dari waktu ke waktu untuk pasien tersebut. Area hijau = rentang rujukan; titik merah = kritis, kuning = abnormal. Berguna untuk kontrol rutin (mis. gula darah, kreatinin).

A12.5. Export CSV & Cetak Worklist

Di menu Hasil Lab:

  • ⬇️ Export CSV — unduh daftar hasil (sesuai filter) untuk diolah di Excel.
  • 🖨️ Worklist — cetak daftar kerja harian (pasien yang perlu dikerjakan/ada hasilnya).

A12.6. Label Barcode Tabung

Di menu Permintaan Lab, tombol 🏷️ Label mencetak label tabung berisi identitas pasien dan barcode Code39. Barcode ini berisi No. Order/RM, sehingga saat tabung dipindai alat, hasil otomatis tercocokkan ke pasien yang benar (lihat Bagian B-5). Ukuran label 50×30 mm.

A12.7. Nilai Rujukan per Gender

Saat mengatur pemeriksaan (menu Alat Laboratorium), selain rujukan umum, tersedia Rujukan Min/Max khusus Laki-laki dan Perempuan. Bila diisi, penentuan flag (normal/low/high/critical) memakai rujukan sesuai gender pasien; bila kosong, memakai rujukan umum.

A12.8. Reload Listener Alat

Setelah menambah alat atau mengubah port, klik 🔁 Reload Listener di menu Alat Laboratorium untuk membuka/menutup port TCP tanpa perlu me-restart backend.

BAGIAN B — TEKNIS & INSTALASI
Bagian ini untuk teknisi/IT: cara kerja koneksi alat, protokol, dan instalasi server.
Kode inti: backend/src/services/instrumentListener.js dan backend/src/services/protocolParsers.js.

1. Model Dasar: LIS sebagai Server, Alat sebagai Client

LIS tidak pernah menghubungi alat. LIS membuka TCP socket server dan menunggu alat yang melakukan koneksi (mode passive listener — standar untuk mayoritas analyzer).

Sysmex XN-1000  ──TCP connect──▶  LIS :5001   (instrument HEM-01)
Roche c501      ──TCP connect──▶  LIS :5002   (instrument CHEM-01)

Konsekuensi di lapangan:

  • Di panel setting alat, isi Host IP = IP server LIS dan Host Port = port yang Anda tetapkan di menu Alat Laboratorium.
  • Belum ada dukungan serial RS-232. Alat yang hanya punya port serial perlu converter serial-to-TCP (mis. Moxa NPort / USR-TCP232) di depannya.

2. Satu TCP Server per Alat

Saat backend start, LIS membaca tabel instruments yang is_active = 1, lalu membuka satu net.createServer() untuk masing-masing di host:port-nya. Default: host = 0.0.0.0, port = 5000.

Seed bawaan:

KodeNamaProtokolPort
HEM-01Hematology Analyzerastm5001
CHEM-01Chemistry Analyzerastm5002
⚠️ PENTING — listener hanya dibuka sekali saat backend boot. Belum ada endpoint reload. Setelah menambah alat baru atau mengubah port lewat UI, Anda wajib me-restart backend agar port-nya benar-benar terbuka: 
pm2 restart geulis-backend
Jika port sudah dipakai proses lain, server gagal diam-diam dan hanya muncul warning EADDRINUSE di log.

Untuk menonaktifkan seluruh listener (mis. saat development), set di backend/.env:

INSTRUMENT_LISTENER_ENABLED=false

3. Protokol yang Didukung

Diset per-alat lewat kolom protocol. Empat protokol tersedia:

ProtokolKegunaan umumBalasan teks LIS
astmSysmex, Roche, Mindray (E1381/E1394)Tidak (hanya <ACK> biner)
hl7Analyzer/middleware berbasis HL7 v2Ya (ACK|n|hl7)
json / tcp_jsonIntegrasi custom / middleware modernYa (ACK|n|json)
xmlIntegrasi custom berbasis XMLYa (ACK|n|xml)

Format pesan yang diharapkan tiap protokol:

  • ASTM — record P (pasien), O (order/barcode), R (hasil), pipe-delimited, diakhiri <EOT> (\x04) atau newline.
  • HL7 v2 — segment PID (pasien), OBR (order, barcode di field 3), OBX (hasil: kode di OBX-3, nilai di OBX-5).
  • JSON — {"sampleId":"ORD001","results":[{"test_code":"HGB","value":"14.2","unit":"g/dL"}]}
  • XML — <sample>ORD001</sample><item code="HGB" value="14.2"/>
Catatan: kolom config_json (mis. {"delimiter":"|"}) tersimpan di DB tetapi belum dibaca oleh parser — delimiter pipe saat ini di-hardcode.

4. Alur Komunikasi End-to-End

┌─────────┐                                          ┌──────────────────────────┐
│  ALAT   │                                          │   LIS (TCP server:port)  │
└────┬────┘                                          └────────────┬─────────────┘
     │  TCP connect                                               │
     │ ─────────────────────────────────────────────────────────▶│
     │                                                            │
     │  <ENQ> (0x05)        [ASTM]                                │
     │ ─────────────────────────────────────────────────────────▶│
     │                                        balas <ACK> (0x06)  │
     │ ◀─────────────────────────────────────────────────────────│
     │                                                            │
     │  frame data (P|... O|... R|...)                            │  buffer += chunk
     │ ─────────────────────────────────────────────────────────▶│  cek isMessageComplete()
     │                                        balas <ACK> [ASTM]  │  log ke instrument_logs
     │ ◀─────────────────────────────────────────────────────────│
     │                                                            │
     │  <EOT> (0x04)        [ASTM]                                │  ── parse & simpan hasil ──
     │ ─────────────────────────────────────────────────────────▶│  socket.end()
     │                                                            │
     │  (non-ASTM) balas ACK|<jumlah tersimpan>|<protokol>        │
     │ ◀─────────────────────────────────────────────────────────│

4a. Buffering & deteksi akhir pesan

TCP adalah stream, bukan pesan — satu pesan alat bisa tiba tercecer dalam beberapa event data. Tiap chunk ditumpuk ke buffer, lalu dicek dengan isMessageComplete():

ProtokolDianggap lengkap bila
astmada <EOT> (\x04), atau baris L|1, atau R| + newline
hl7ada \x1C (FS/MLLP), atau OBX| + diakhiri newline
jsonJSON.parse() berhasil
xmlada tag penutup </…>

Jika belum lengkap → tunggu chunk berikutnya. Jika lengkap → buffer diproses lalu dikosongkan.

4b. Handshake ASTM (ENQ / ACK / EOT)

Khusus astm, LIS membalas otomatis:

  • Chunk mengandung <ENQ> (\x05) → balas <ACK> (\x06) = "silakan kirim".
  • Chunk mengandung newline tapi bukan <EOT> → balas <ACK> = "frame diterima".
  • <EOT> (\x04) diterima → socket.end(), koneksi ditutup rapi.
Untuk ASTM, LIS tidak pernah mengirim teks seperti ACK|3|astm (Sysmex akan error bila dikirimi teks bebas setelah EOT). Balasan teks ACK|n|protokol / NAK|pesan hanya untuk JSON/HL7/XML.

5. Parsing → Pencocokan Pasien → Penyimpanan

5a. Yang diambil dari pesan

Parser hanya mencari dua hal: ID sampel (barcode) dan daftar hasil (plus data pasien opsional: nama, tgl lahir, gender). Contoh penanganan khusus Sysmex:

  • Kode tes berformat ^^^^WBC^1 → diekstrak menjadi WBC.
  • Pemisah baris hanya \r (bukan \n) tetap didukung.

5b. Pencocokan barcode ke pasien

Barcode dicari sekaligus ke 4 kolom (resolvePatientId):

  • patients.medical_record_no
  • patients.order_no
  • lab_requests.request_no
  • lab_requests.simrs_order_id

Jadi barcode boleh berisi No. RM atau No. Order SIMRS — keduanya cocok. Bila tidak ditemukan sama sekali, pasien dibuat otomatis (nama dari record P atau Pasien <barcode>), plus satu lab_requests berstatus completed.

5c. Auto-mapping kode tes

Sebelum menyimpan, tiap kode tes dari alat dicek di instrument_test_map. Bila belum ada mapping-nya, kode itu otomatis didaftarkan ke lab_tests sekaligus dibuatkan mapping-nya.

Praktis untuk setup awal: jalankan satu sampel, semua parameter alat langsung muncul di menu Alat Laboratorium, tinggal Anda rapikan nama/satuan/nilai rujukannya.

5d. Perhitungan flag

KondisiFlag
nilai < reference_minlow

nilai > reference_maxhigh

6. Komunikasi Dua Arah — Host Query (ASTM saja)

Fitur worklist otomatis: alat menanyakan "tabung ini mau diperiksa apa?" dan LIS menjawab dengan daftar tes yang sudah di-order.

Alat scan barcode tabung
   │
   ├──▶ kirim record  Q|...|077071          "tabung ini mau diperiksa apa?"
   │
   │    LIS: cari lab_requests dari barcode → ambil lab_request_items
   │         → terjemahkan ke kode alat via instrument_test_map
   │
   ◀──── H|…   P|1   O|1|077071||^^^WBC\^^^^HGB…|…|Q   L|1|N
   │
   └──▶ alat langsung menjalankan tes yang diminta, tanpa input manual

Bila order tidak ditemukan atau tidak ada tes yang ter-mapping, buildAstmOrder() mengembalikan string kosong → LIS tidak membalas → alat biasanya jatuh ke mode default/manual.

7. Logging

Setiap chunk masuk dan setiap balasan dicatat ke tabel instrument_logs, dengan control character diubah menjadi teks terbaca agar bisa dibaca di UI: <ENQ>, <ACK>, <EOT>, <STX>, <ETX>.

  • 50 log terakhir tampil via GET /api/instruments/logs/recent (menu Alat Laboratorium).
  • Kolom instruments.last_connected diperbarui tiap ada data masuk.
  • Debug log mentah ditulis ke /tmp/lis_debug.log (⚠️ path Unix — tidak berfungsi di Windows Server; tanpa rotasi).

8. Ringkasan Konfigurasi Alat

Di menu Alat Laboratorium LIS, tiap alat memiliki:

FieldKeterangan
codeKode unik alat (mis. HEM-01)
nameNama alat
protocolastm / hl7 / json / xml
hostInterface listen LIS (default 0.0.0.0)

Di sisi alat: set Host = IP server LIS, Port = port di atas, protokol/format output sesuaikan dengan kolom protocol.

Setelah perubahan port / alat baru → restart backend.

9. Catatan Keterbatasan (Perlu Diwaspadai)

Beberapa hal yang perlu diperhatikan untuk pemakaian produksi dengan data medis:

  1. Frame number ASTM belum di-strip. ASTM ter-frame mengirim <STX> + nomor frame + isi + <CR><ETX> + checksum. Kode membuang <STX>/<ETX> tetapi tidak nomor frame/checksum, sehingga record bisa jadi 2P|1|... dan terlewat karena parser mencocokkan parts[0] === 'P'. Aman hanya bila alat mengirim baris polos tanpa framing.
  2. Checksum tidak divalidasi. Frame rusak diterima apa adanya sebagai hasil pasien.
  3. ACK dikirim per-chunk, bukan per-frame. Bila satu chunk TCP memuat dua frame, ACK bisa kurang; bila satu frame terpecah dua chunk, ACK bisa dobel. Sebagian analyzer toleran, sebagian bisa timeout/retry.
  4. Listener tidak reload otomatis — lihat peringatan di Bagian 2.

10. Panduan Instalasi (Setup s/d Terima Hasil)

10.1. Prasyarat

  • Database: MySQL / MariaDB (mis. lewat XAMPP — Control Panel → Start MySQL).
  • Node.js 18.x / 20.x+.
  • Server LIS dan alat berada dalam satu jaringan (bisa saling ping).

10.2. Import Database (XAMPP)

Dump database/dump_contoh.sql tidak memuat CREATE DATABASE, jadi buat dulu database-nya baru import ke dalamnya.

# path mysql XAMPP di macOS:
MYSQL=/Applications/XAMPP/xamppfiles/bin/mysql
# (Windows XAMPP: C:\xampp\mysql\bin\mysql.exe)

# 1. buat database
"$MYSQL" -u root -e "CREATE DATABASE IF NOT EXISTS geulis CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"

# 2. import dump
"$MYSQL" -u root geulis < database/dump_contoh.sql

# 3. verifikasi
"$MYSQL" -u root geulis -e "SHOW TABLES;"

Alternatif lewat phpMyAdmin (http://localhost/phpmyadmin): buat database geulis → tab Import → pilih database/dump_contoh.sql → Go.

10.3. Konfigurasi Credential (backend/.env)

Default XAMPP: user root, tanpa password. Isi backend/.env:

PORT=3001
JWT_SECRET=ganti-dengan-teks-acak-panjang
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=
DB_NAME=geulis
INSTRUMENT_LISTENER_ENABLED=true
Gunakan 127.0.0.1 (bukan localhost) agar driver mysql2 konek via TCP ke MariaDB XAMPP. Jika MySQL Anda berpassword, isi DB_PASSWORD.

10.5. Mendaftarkan Alat & Menghubungkannya

  1. Login sebagai admin → menu Alat Laboratorium → Tambah Alat.
  2. Isi code, name, pilih protocol (mis. astm), dan Port TCP (mis. 5005). Pastikan is_active menyala.
  3. Restart backend agar port listener terbuka (lihat Bagian 2) — pm2 restart geulis-backend atau hentikan & jalankan ulang npm start.
  4. Di panel setting alat (mis. Sysmex): set Host/IP = IP server LIS, Port = 5005, mode output sesuai protokol.
  5. Kirim satu sampel uji. Buka menu Alat Laboratorium → log untuk memastikan data masuk (<ENQ>, <ACK>, record R|...).
