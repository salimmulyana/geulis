# Mindray BC-3600 — Integrasi dengan GeuLIS

Dokumen khusus untuk analyzer hematologi **Mindray BC-3600** (`HTM001`).
Untuk gambaran umum komunikasi alat, lihat [KOMUNIKASI_ALAT.md](KOMUNIKASI_ALAT.md).

Sumber: manual resmi `BC-3600_handbuch.pdf` (operator's manual, 320 halaman),
terutama bagian **5.2.2 Transmission** dan **Appendix D.3 Network Port Connection**,
diverifikasi langsung terhadap alat di lapangan pada 3 September 2026.

---

## 1. Hal terpenting: arah koneksinya terbalik

**BC-3600 adalah TCP server. LIS yang harus menghubungi alat**, bukan sebaliknya.

Ini kebalikan dari mayoritas analyzer (mis. Sysmex XN-330 yang dipakai sebelumnya,
yang menghubungi LIS). Manual menyatakannya di D.3:

> "After starting up, the analyzer **monitors the message sent by LIS**. After
> connection is built, the analyzer sends heartbeat control code **0x02 once in
> 3 seconds**."

```
GeuLIS 192.168.1.14  ──TCP connect──▶  BC-3600 192.168.1.200:3600
                     ◀── 0x02 tiap 3 detik (heartbeat)
                     ◀── pesan HL7 saat ada hasil
```

Konsekuensi yang wajib dipahami: **listener TCP-server GeuLIS tidak akan pernah
menerima apa pun dari BC-3600.** Alat ini hanya bisa dilayani lewat mode client.

### Kenapa tidak ada setting "IP server LIS" di alat

Karena alat tidak pernah menginisiasi koneksi, ia tidak perlu tahu alamat LIS.
Manual bagian 5.2.2 hanya menyediakan tiga isian pada mode network:

> "Enter the legitimate addresses into the *IP address*, *Subnet mask* and
> *Default gateway* boxes, the *Mac address* box cannot be edited."

Ketiganya adalah identitas alat sendiri. Mencari menu "host IP" di alat ini
adalah usaha yang sia-sia — memang tidak ada, dan tidak dibutuhkan.

## 2. Alamat dan port

| Item | Nilai |
|---|---|
| IP alat | `192.168.1.200` |
| Port data LIS | `3600` |
| MAC | `00:0F:14:0A:57:F8` (Mindray) |
| IP server GeuLIS | `192.168.1.14` (antarmuka LAN `enp2s0`) |

Port lain yang terbuka di alat: `23` (telnet konsol board ColdFire — bukan jalur
data, jangan dipakai) dan `6600` (tidak merespons).

> **Jangan pakai `<alamat-tailscale-server>`.** Itu alamat Tailscale server, hanya untuk akses
> web/admin dari luar. Untuk komunikasi alat, yang berlaku adalah IP LAN
> `192.168.1.14`.

Cara memastikan port data hidup:

```bash
nmap -Pn -p- 192.168.1.200        # harus muncul 23, 3600, 6600
```

Port `3600` dan `6600` **tidak** termasuk daftar port lazim, sehingga pemindaian
port umum saja tidak akan menemukannya. Gunakan `-p-`.

## 3. Setting di panel alat

Menu: **Setup → System Setup → Transmission**

| Setting | Nilai | Catatan |
|---|---|---|
| Transmit type | **Network port transmit** | bukan serial |
| IP address | `192.168.1.200` | identitas alat sendiri |
| Subnet mask | `255.255.255.0` | |
| Default gateway | `192.168.1.1` | |
| Transmit protocol | **HL7** | pilihan lain: 15ID, 15ID+2 |
| ACK synchronous transmission | **tidak dicentang** | lihat catatan di bawah |
| Auto retransmit | On | kirim ulang setelah jaringan tersambung lagi |
| **Auto transmit** | **On** | **wajib** — lihat di bawah |

### Auto transmit wajib On

Manual bagian 5.2.2:

> "When the *Auto transmit* function is On, the analyzer will send results to the
> external computer automatically; when the function is Off, the analyzer will
> **not** send results to the external computer automatically."

Selama `Auto transmit` masih `Off`, petugas boleh menjalankan berapa pun sampel
dan LIS tetap tidak menerima apa-apa — koneksi tetap terbentuk, tapi tidak ada
hasil yang dikirim. Ini penyebab paling umum "alat sudah nyambung tapi kok kosong".

Setelah mengubah setting, keluar dari layar lewat menu/tombol lain, lalu pilih
**Yes** pada dialog konfirmasi agar perubahan tersimpan.

### ACK synchronous transmission dibiarkan mati

Bila diaktifkan, alat menunggu balasan ACK ber-format HL7 (segmen MSA) dari LIS.
GeuLIS saat ini membalas teks sederhana `ACK|<jumlah>|hl7`, **bukan** ACK HL7
standar. Selama opsi ini mati, alat tidak menunggu balasan dan semuanya aman.
Jangan aktifkan sebelum GeuLIS bisa membalas MSA yang benar.

## 4. Konfigurasi di sisi GeuLIS

Baris pada tabel `instruments`:

| Kolom | Nilai |
|---|---|
| `code` | `HTM001` |
| `name` | `Mindray BC-3600` |
| `protocol` | `hl7` |
| `conn_mode` | `client` |
| `host` | `192.168.1.200` |
| `port` | `3600` |
| `is_active` | `1` |

Kolom **`conn_mode`** ditambahkan khusus untuk kasus ini
([`ensureSchema.js`](../backend/src/ensureSchema.js), migrasi otomatis saat backend start):

- `server` — alat yang menghubungi LIS (perilaku lama, mis. Sysmex/ASTM)
- `client` — LIS yang menghubungi alat (BC-3600)

Mengubah `conn_mode`, `host`, atau `port` tidak memerlukan restart backend;
`reloadInstrumentListeners()` akan menutup koneksi lama dan membuka yang baru.

### Perilaku konektor client

Ada di [`instrumentListener.js`](../backend/src/services/instrumentListener.js):

- Menghubungi `host:port` saat backend start
- **Menyambung ulang otomatis tiap 5 detik** bila koneksi putus atau alat mati
- Heartbeat `0x02` **dibuang total** — tidak di-buffer, tidak dicatat. Tanpa ini
  tabel `instrument_logs` akan terisi ±28.800 baris kosong per hari
- Koneksi yang berhasil dicatat sebagai baris log `koneksi ke <host>:<port> terbentuk`,
  dan `instruments.last_connected` diperbarui

## 5. Format pesan HL7 dari BC-3600

Contoh pesan nyata (dibungkus MLLP: `0x0B` di depan, `0x1C 0x0D` di belakang):

```
MSH|^~\&|BC-3600|Mindray|||20260903090000||ORU^R01|1|P|2.3.1||||||UNICODE
PID|1||0000123456^^^^MR||BUDI SANTOSO||19900101|M
OBR|1||0000123456|00001^Automated Count^99MRC|||20260903090000
OBX|1|IS|08001^Take Mode^99MRC||A||||||F
OBX|2|NM|6690-2^WBC^LN||7.25|10*9/L|4.0-10.0|N|||F
OBX|3|NM|718-7^HGB^LN||13.4|g/dL|11.0-16.0|N|||F
```

Yang diambil GeuLIS ([`protocolParsers.js`](../backend/src/services/protocolParsers.js)):

| Segmen | Diambil |
|---|---|
| `PID-3` | nomor sampel / barcode |
| `PID-5`, `PID-7`, `PID-8` | nama, tanggal lahir, jenis kelamin |
| `OBR-3` | nomor sampel (cadangan) |
| `OBX-3` | kode tes |
| `OBX-5`, `OBX-6` | nilai dan satuan |

### Dua aturan penting pada OBX

**1. Nama tes diutamakan, bukan kode LOINC.** `6690-2^WBC^LN` dibaca sebagai
`WBC`, bukan `6690-2`. Kalau nama komponennya mengandung spasi
(mis. `Neutrophil Percent`), parser sengaja mundur ke kode aslinya, karena nama
bersepasi bukan kode tes yang wajar.

**2. OBX bertipe `IS`, `TX`, `FT` dilewati.** BC-3600 mengirim informasi non-hasil
seperti `Take Mode` dan `Blood Mode` sebagai segmen OBX. Tanpa penyaringan ini,
keduanya akan tersimpan sebagai "hasil pemeriksaan" dan mengotori data.

OBX bertipe **`ST` sengaja TIDAK dilewati**, agar hasil kualitatif yang sah tidak
ikut terbuang. Efek sampingnya, segmen seperti `Error Message` bisa muncul sebagai
tes — abaikan lewat menu mapping bila mengganggu.

## 6. Nomor sampel harus cocok

BC-3600 memakai HL7, dan **host query tidak tersedia pada jalur HL7** — alat tidak
bisa menanyakan daftar order ke LIS. Artinya nomor sampel/barcode **harus diketik
atau di-scan di alat**, dan nilainya harus cocok dengan salah satu dari:

- `patients.medical_record_no`
- `patients.order_no`
- `lab_requests.request_no`
- `lab_requests.simrs_order_id`

**Bila tidak cocok, hasil tetap masuk — tetapi GeuLIS membuatkan pasien baru
otomatis** bernama `Pasien <nomor sampel>`, bukan menempelkannya ke order yang ada.
Salah ketik barcode karena itu menghasilkan "pasien hantu", bukan pesan error yang
kelihatan. Ini titik paling rawan dalam operasional sehari-hari.

## 7. Flag H/L berasal dari GeuLIS, bukan dari alat

BC-3600 mengirimkan flagnya sendiri di `OBX-8`, tetapi GeuLIS **mengabaikannya**
dan menghitung ulang dari nilai rujukan di tabel `lab_tests` (lihat
[`flags.js`](../backend/src/services/flags.js), mendukung rujukan terpisah
laki-laki/perempuan).

Tes yang terbentuk otomatis dari pesan alat **belum punya nilai rujukan**, sehingga
semua hasilnya akan berflag `normal` meski nilainya ekstrem. **Isi nilai rujukan
setiap tes lewat menu Tes Lab** sebelum sistem dipakai untuk keputusan klinis.

## 8. Diagnostik

```bash
# 1. Alat hidup dan port data terbuka?
nmap -Pn -p- 192.168.1.200

# 2. Alat benar-benar BC-3600? (harus mengirim 0x02 tiap 3 detik)
timeout 11 nc 192.168.1.200 3600 | xxd

# 3. LIS sudah tersambung ke alat?
ss -tn state established '( dport = :3600 )'

# 4. Apa kata backend?
pm2 logs geulis-backend --lines 50 | grep Instrument
#    -> [Instrument] HTM001 (hl7) client -> 192.168.1.200:3600 terhubung

# 5. Lalu lintas mentah
tail -f /tmp/lis_debug.log
```

Semua pesan juga tercatat di tabel `instrument_logs` dan tampil di menu **Alat**
pada web GeuLIS.

### Gejala umum

| Gejala | Sebab paling mungkin |
|---|---|
| Log berhenti di "terbentuk", tidak ada hasil | `Auto transmit` masih `Off` di alat |
| Tidak pernah tersambung | Alat mati, kabel LAN lepas, atau `conn_mode` masih `server` |
| Hasil masuk tapi pasiennya baru semua | Nomor sampel di alat tidak cocok dengan order di LIS (bagian 6) |
| Muncul "tes" aneh seperti `08003` | Segmen OBX bertipe `ST`; abaikan lewat mapping (bagian 5) |
| Semua flag `normal` padahal nilai ekstrem | Nilai rujukan tes belum diisi (bagian 7) |

## 9. Batasan yang diketahui

- **Host query / worklist tidak tersedia.** Hanya jalur ASTM yang mendukungnya di
  GeuLIS, sedangkan BC-3600 pada mode network hanya menawarkan 15ID, 15ID+2, dan HL7.
- **ACK HL7 standar (MSA) belum diimplementasikan.** Karena itu
  `ACK synchronous transmission` di alat harus tetap mati.
- **Protokol 15ID / 15ID+2 belum didukung** GeuLIS. Hanya HL7 yang dipakai.

## 10. Cadangan: jalur serial RS-232

Tidak diperlukan selama jalur LAN berfungsi, dan **GeuLIS belum bisa membaca port
serial** (perlu penambahan kode). Dicatat untuk keadaan darurat.

Dari manual bagian 4.4.4 — port serial alat adalah **9-pin male**, kabelnya lurus
(*direct-connected*) dengan dua ujung female:

| Pin | Sinyal | Fungsi |
|---|---|---|
| 2 | TXD | kirim data (output) |
| 3 | RXD | terima data (input) |
| 5 | GND | ground |
| 7 | CTS | izin kirim (input) |
| 8 | RTS | minta kirim (output) |

Parameter serial: 9600 / None / 8 / 1. Protokol serial yang tersedia lebih banyak:
8ID, 10ID, 15ID, 15ID+2, HL7.

Cara termudah bila jalur ini terpaksa dipakai adalah konverter serial→Ethernet
(Moxa NPort, USR-TCP232) dalam mode **TCP Server**, lalu GeuLIS menghubunginya
seperti menghubungi alat — tanpa perubahan kode.
