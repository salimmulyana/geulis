# Mindray BC-11 — Integrasi dengan GeuLIS (lokasi pemasangan lain)

Analyzer hematologi Mindray BC-11, terpasang di lokasi pemasangan lain dan terhubung ke
GeuLIS di `192.168.2.253`.

Untuk gambaran umum komunikasi alat lihat [KOMUNIKASI_ALAT.md](KOMUNIKASI_ALAT.md);
untuk BC-3600 di salah satu lokasi pemasangan lihat [BC-3600.md](BC-3600.md).

---

## 1. Alamat dan arah koneksi

**Alat adalah TCP server. GeuLIS yang menghubungi**, sama seperti BC-3600.

```
GeuLIS 192.168.2.253  ──menghubungi──▶  BC-11 192.168.2.244:5100
                      ◀── detak 0x02 tiap 3 detik
                      ◀── hasil HL7, dan permintaan worklist
```

| Item | Nilai |
|---|---|
| IP alat | `192.168.2.244` |
| **Port data** | **`5100`** |
| MAC | `00:0F:14:35:12:78` (Mindray) |
| Protokol | HL7 v2.3.1 (MLLP) |
| Server GeuLIS | `192.168.2.253` |

Port `5100` **berbeda dari BC-3600 yang memakai 3600**. Tiap keluarga alat Mindray
punya portnya sendiri, jadi jangan diasumsikan sama. Cara memastikannya:

```bash
nmap -Pn -p- 192.168.2.244        # BC-11: terbuka 21, 23, 5100, 6600
timeout 11 nc 192.168.2.244 5100 | xxd   # harus 0x02 tiap 3 detik
```

Alat ini **tidak menjawab ping** (ICMP diblokir), jadi jangan pakai ping untuk
menyimpulkan alat mati — pakai `nmap` atau ARP.

## 2. Setting di panel alat

Menu **Setup → Communication**.

| Setting | Nilai | Catatan |
|---|---|---|
| Communication | Network port comm. | bukan serial |
| IP / Subnet / Gateway | `192.168.2.244` / `255.255.255.0` / `192.168.2.1` | identitas alat sendiri |
| Comm Protocol | **HL7** | |
| ACK Synchronous Transmission | **boleh hidup** | GeuLIS membalas `ACK^R01` yang sah |
| ACK Overtime | 10 detik | |
| Auto Retransmit | hidup | kirim ulang bila gagal |
| **Auto Communicate** | **HIDUP — wajib** | tanpa ini hasil tidak dikirim sama sekali |
| **Auto Fetch Info From LIS** | **boleh hidup** | worklist; lihat bagian 3 |
| Transmit as Print Bitmap Data | sebaiknya mati | muatan cetak yang tidak dipakai LIS |
| Histogram transmitted as | sebaiknya **Not to be transmitted** | mengurangi lalu lintas |

## 3. Worklist — alat menarik identitas pasien dari LIS

Ini yang membedakan BC-11 dari BC-3600. Dengan `Auto Fetch Info From LIS` hidup,
petugas cukup **scan barcode**; identitas pasien turun otomatis dari GeuLIS ke
alat, tanpa mengetik apa pun.

### Alur pesan

```
alat  ──ORM^O01──▶  GeuLIS      "siapa pasien untuk sampel 122?"
GeuLIS ──ORR^O02──▶ alat        identitas pasien + order
```

**Permintaan dari alat** (direkam langsung dari alat produksi):

```
MSH|^~\&|||||20260903080133||ORM^O01|1|P|2.3.1||||||UNICODE
ORC|RF||122||IP
```

- `ORC-1 = RF` — *re-fill order request*
- `ORC-3 = 122` — nomor sampel yang ditanyakan

**Balasan GeuLIS bila pasien ditemukan:**

```
MSH|^~\&|LIS||||20260903082153||ORR^O02||P|2.3.1||||||UNICODE
MSA|AA|1
PID|1||122^^^^MR||^SITI AMINAH||19880417|F
ORC|AF|122
OBR|1|122||00001^Automated Count^99MRC
```

- `MSA-2` mengembalikan `MSH-10` pesan masuk
- `ORC-1 = AF` — *affirm the re-filled order*
- Nomor sampel pindah ke `ORC-2` dan `OBR-2`

**Bila tidak ditemukan:**

```
MSH|...||ORR^O02||P|2.3.1||||||UNICODE
MSA|AE|1
```

Sengaja tanpa `PID` dan `ORC`. GeuLIS **tidak mengarang identitas pasien**, karena
alat menampilkannya langsung ke petugas — data palsu di layar alat lebih berbahaya
daripada pesan "tidak ditemukan".

### Nomor sampel dicocokkan dengan

`patients.medical_record_no`, `patients.order_no`, `lab_requests.request_no`, atau
`lab_requests.simrs_order_id`.

### Catatan penting soal jenis pesan

BC-11 memakai **ORM/ORR**, **bukan** `QRY^Q02`/`QCK^Q02`/`DSR^Q03` yang tertulis di
*Mindray Host Interface Manual Ver 4.0*. Dokumentasi Mindray berbeda antar generasi
alat. Karena itu pesan aslinya **direkam dulu dari alat** sebelum kode ditulis —
menebak dari dokumen yang salah akan menghasilkan kode yang tidak pernah cocok.

Untuk alat lain, rekam dulu dengan cara yang sama: pesan mentah masuk tercatat di
tabel `instrument_logs` dan di `/tmp/lis_debug.log` pada server.

## 4. Diagnostik

```bash
# koneksi GeuLIS ke alat hidup?
ss -tn state established '( dport = :5100 )'

# apa kata backend
pm2 logs geulis-backend --lines 50 | grep Instrument
#  -> [Instrument] HTM001 (hl7) client -> 192.168.2.244:5100 terhubung

# lalu lintas mentah (heartbeat 0x02 sudah disaring, tidak muncul di sini)
tail -f /tmp/lis_debug.log
```

Semua pesan juga tercatat di tabel `instrument_logs` dan tampil di menu **Alat**
pada web GeuLIS, termasuk baris `worklist <barcode> -> <nama pasien>`.

| Gejala | Sebab paling mungkin |
|---|---|
| Log berhenti di "terbentuk", hasil tidak datang | `Auto Communicate` mati di alat |
| Worklist selalu "tidak ditemukan" | Nomor sampel tidak cocok dengan order di GeuLIS |
| Tidak pernah tersambung | Alat mati atau kabel LAN lepas — **jangan pakai ping**, alat memblokir ICMP |
| Hasil masuk tapi pasiennya baru semua | Barcode salah ketik dan worklist tidak dipakai |

## 5. Konfigurasi di GeuLIS

| Kolom `instruments` | Nilai |
|---|---|
| `code` | `HTM001` |
| `name` | `Mindray BC-11` |
| `protocol` | `hl7` |
| `conn_mode` | `client` |
| `host` | `192.168.2.244` |
| `port` | `5100` |
| `is_active` | `1` |

Mengubah host/port tidak perlu restart backend — listener dimuat ulang sendiri.
